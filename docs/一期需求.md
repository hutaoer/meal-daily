一、项目概述
你希望开发一款基于 Taro 框架的多端美食 APP（支持小程序 + APP），核心解决程序员等职场人群带饭选择难的问题，主打「制作简单、每日不重样」的带饭菜谱。本次调整后暂不包含后台管理功能，聚焦前端用户侧核心体验，支持用户自主上传菜谱（无需审核直接发布），通过标签、评论等功能增加互动性，契合消费降级背景下自己带饭的需求。
二、核心需求整理
2.1 核心目标
解决用户带饭「吃什么」的选择困难，提供随机 / 主题化菜谱推荐
聚焦「制作简单」的带饭菜谱，适配职场人群的时间和操作能力
支持多端使用（小程序 + APP），兼顾便捷性和体验
支持用户自主上传菜谱，形成轻量化内容生态
通过标签、评论提升互动性，增强用户粘性
2.2 功能需求
2.2.1 基础功能模块
表格
模块	子功能	详细说明
首页	1. 随机菜谱推荐	点击「今日吃什么」按钮，随机推荐 1 款符合「制作简单」的带饭菜谱
2. 主题菜谱分类	按主题分类（如：15 分钟快手、一人食、低卡减脂、家常菜、时令蔬菜）
3. 热门 / 推荐菜谱	展示点赞 / 收藏量高的菜谱，按热度排序
菜谱详情	1. 基础信息展示	菜名、难度（简单 / 中等）、制作时长、食材清单（含用量）、步骤（图文 / 文字）
2. 标签展示	展示菜谱标签（如：快手、低卡、下饭、素食）
3. 互动功能	点赞、收藏、评论、分享（分享到微信 / 朋友圈 / 复制链接）
4. 相关推荐	推荐同类 / 相似菜谱
菜谱上传	1. 用户自主上传	前端提交，无需审核直接发布；需填写：菜名、难度、时长、食材、步骤、标签，支持上传图片
2. 草稿保存	支持保存未完成的上传内容，避免误操作丢失
3. 菜谱编辑 / 删除	用户可编辑 / 删除自己上传的菜谱
分类 / 搜索	1. 分类筛选	按标签（如：快手、低卡）、时长（≤15 分钟 / 15-30 分钟）、难度筛选
2. 关键词搜索	支持搜索菜名、食材、标签（如：搜索「鸡蛋」显示含鸡蛋的带饭菜谱）
个人中心	1. 个人信息	昵称、头像、简介（基于小程序 / APP 授权的基础信息，无需额外注册）
2. 我的内容	我上传的菜谱、我收藏的菜谱、我的点赞 / 评论
3. 反馈建议	提交使用中的问题 / 建议（轻量化表单，提交后本地存储或导出为文本）
2.2.2 非功能需求
表格
类型	详细要求
多端适配	基于 Taro 开发，兼容微信小程序、Android APP、iOS APP，界面适配不同设备尺寸
性能	页面加载时间≤3 秒，图片懒加载，本地缓存常用菜谱数据
兼容性	小程序兼容微信基础库 2.0 以上版本，APP 兼容 Android 8.0+/iOS 11.0+
易用性	操作流程简单，菜谱步骤清晰易懂，上传表单逻辑简化，降低用户操作成本
轻量化	APP 包体大小≤50MB，小程序代码包≤2MB，减少用户下载 / 加载成本
数据存储	1. 前端：使用本地存储（LocalStorage / 小程序缓存）保存用户收藏、草稿等数据
2. 云端：使用轻量云数据库（如微信云开发 / 阿里云轻量数据库）存储菜谱、用户互动数据
隐私性	仅收集必要的用户信息（头像、昵称），不上传敏感数据
2.3 核心约束
菜谱核心定位：必须满足「制作简单」，步骤≤8 步，时长≤30 分钟（特殊标注除外）；
无审核机制：用户上传内容需通过前端文案引导（如「请发布合规、健康的菜谱内容」），暂不做人工审核；
多端一致性：核心功能（随机推荐、菜谱详情、上传）在小程序和 APP 端体验一致；
无后台依赖：所有核心功能可基于前端 + 轻量云服务实现，无需独立部署后台管理系统。
三、用户角色与场景
3.1 核心用户角色
表格
角色	特征与使用场景
普通用户	职场程序员 / 上班族，每天需要带饭，纠结吃什么，希望快速找到简单易做的菜谱；同时可上传自己的拿手带饭菜谱，无需审核直接分享
3.2 典型使用场景
场景 1：用户早上出门前不知道带什么饭，打开 APP 点击「今日吃什么」按钮，快速获取 1 款 15 分钟能做好的带饭菜谱；
场景 2：用户想做低卡减脂的带饭菜，在分类中选择「低卡减脂」标签，筛选出符合要求的菜谱；
场景 3：用户做了一款简单的番茄炒蛋，通过「上传菜谱」功能填写食材、步骤、标签后提交，无需审核直接发布到平台；
场景 4：用户发现自己上传的菜谱有错误，进入「我的上传」页面编辑菜谱内容，或删除不合适的菜谱。
四、优先级划分
表格
优先级	功能模块	说明
P0（核心）	首页随机推荐、菜谱详情、基础分类	满足用户核心「找菜谱」需求
P1（重要）	菜谱上传（免审核）、菜谱编辑 / 删除	完善用户内容发布闭环

五、原型参考（文字描述）
5.1 首页布局
顶部：搜索栏 + 「今日吃什么」随机按钮（醒目，居中 / 偏上）；
中部：主题分类入口（横向滑动，如：15 分钟快手、一人食、低卡减脂）；
底部：热门菜谱列表（图文卡片，展示菜名、时长、难度、封面图）。
5.2 菜谱详情页
顶部：菜谱封面图 + 菜名、难度、时长；
中部：食材清单（分点列出）、制作步骤（按序号排列，支持图文）；
底部：标签栏 + 点赞 / 收藏 / 评论按钮 + 评论区。
5.3 上传菜谱页
表单式布局（简化版）：依次填写菜名 → 选择难度 / 时长 → 填写食材（多行添加） → 填写步骤（多行 + 图片） → 选择标签 → 一键发布（无审核步骤）；
辅助功能：「保存草稿」按钮，支持随时保存未完成内容。
5.4 个人中心页
顶部：用户头像 + 昵称；
中部：功能入口（我的上传、我的收藏、我的评论）；
底部：反馈建议入口 + 关于 APP 说明。
六、技术选型建议（轻量化）
前端框架：Taro 3.x（支持多端编译，适配小程序 / APP）；
UI 组件库：Taro UI / NutUI（适配多端的轻量组件库）；
数据存储：
小程序端：微信云开发（云数据库 + 云存储，无需自建服务器）；
APP 端：阿里云轻量数据库（如 RDS MySQL） + 阿里云 OSS（图片存储）；
部署：
小程序：直接部署到微信公众平台；
APP：Taro 编译打包后，发布到应用商店 / 蒲公英等内测平台。
总结
核心聚焦用户侧体验，砍掉后台管理功能后，用户上传菜谱免审核直接发布，简化内容生产流程，降低开发和维护成本；
数据存储采用「前端本地缓存 + 轻量云服务」的轻量化方案，无需搭建复杂后台，适配初期快速上线的需求；
核心功能仍围绕「解决带饭选择难」，保留随机推荐、简单菜谱分类等核心能力，同时保证多端适配和轻量化体验。
