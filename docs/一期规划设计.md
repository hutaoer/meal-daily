# meal-daily 一期规划设计文档

> 版本：v1.0 | 日期：2026-03-02 | 作者：前端团队

---

## 一、项目概述

**项目名称**：meal-daily（每日带饭菜谱）

**核心价值**：解决职场人群带饭「吃什么」的选择困难，主打「制作简单、每日不重样」的带饭菜谱推荐平台。

**技术栈**：
- 框架：Taro 3.6.x（React + TypeScript）
- 样式：SCSS
- 端：微信小程序（优先）+ APP（React Native）
- 数据：一期使用 Mock 数据，后续切换为微信云开发 / 腾讯云函数

## 二、整体架构设计

### 2.1 架构分层

```
┌─────────────────────────────────────────────────────┐
│                    视图层（Pages）                    │
│   首页 / 菜谱详情 / 上传 / 分类搜索 / 个人中心         │
├─────────────────────────────────────────────────────┤
│                  组件层（Components）                 │
│   通用组件 / 业务组件                                 │
├─────────────────────────────────────────────────────┤
│                  服务层（Services）                   │
│   Mock Service → 后续替换为 Cloud Functions API       │
├─────────────────────────────────────────────────────┤
│             状态管理层（Store / Hooks）               │
│   用户信息 / 收藏 / 草稿 / 登录态                     │
├─────────────────────────────────────────────────────┤
│                  工具层（Utils）                      │
│   本地缓存 / 图片处理 / 常量 / 类型定义                │
└─────────────────────────────────────────────────────┘
```

### 2.2 数据流图

```
用户操作
   │
   ▼
Page / Component
   │  调用
   ▼
Services（一期：Mock，后期：云函数）
   │  返回数据
   ▼
全局 Store（useContext / Zustand）
   │  更新
   ▼
本地缓存（Taro.setStorageSync）
```

### 2.3 微信授权登录流程

```
用户进入 APP
   │
   ▼
检查本地缓存 token / openid
   │ 无缓存
   ▼
调用 Taro.login() → 获取 code
   │
   ▼
调用云函数 login（一期 Mock 本地模拟）
   │  返回 openid + token
   ▼
存储到 Storage + 全局 Store
   │
   ▼
拉取用户信息（头像、昵称）→ 展示个人中心
```

> **一期 Mock 方案**：直接生成一个随机 `mockOpenId`，存储到 Storage，模拟已登录态，无需真实调用微信 API。

## 五、Mock 数据策略

### 5.1 整体方案

一期所有接口均通过 **Mock Service** 实现：

```
services/request.ts
   │
   ├── 开发模式（process.env.NODE_ENV === 'development'）
   │       └──→ 调用 Mock Service（本地 JSON 数据 + 延迟模拟）
   │
   └── 生产模式
           └──→ 调用云函数 API（后续切换）
```

通过环境变量 `.env.dev` 中 `TARO_APP_USE_MOCK=true` 控制切换。

### 5.2 Mock 数据规模

| 数据类型 | 数量 | 说明 |
|---------|------|------|
| 菜谱 | 30 条 | 覆盖 5 个主题分类，含完整字段 |
| 分类 | 5 个 | 15分钟快手、一人食、低卡减脂、家常菜、时令蔬菜 |
| 评论 | 每菜谱 3~5 条 | 随机用户名、时间 |
| 用户 | 1 条（当前用户） | Mock openId + 头像 + 昵称 |

### 5.3 Mock Recipe 数据结构

```typescript
interface Recipe {
  id: string;                    // 唯一 ID
  title: string;                 // 菜名
  coverImage: string;            // 封面图 URL（可用 picsum.photos 随机图）
```

## 六、微信授权登录方案

### 6.1 一期 Mock 登录（无需真实微信调用）

```typescript
// services/user.service.ts
export const mockLogin = async () => {
  const cached = Taro.getStorageSync('userInfo');
  if (cached) return cached;

  // 模拟登录成功，生成 Mock 用户
  const mockUser = {
    openId: 'mock_openid_' + Math.random().toString(36).slice(2),
    nickName: '带饭达人',
    avatarUrl: 'https://api.dicebear.com/7.x/fun-emoji/svg?seed=meal',
    token: 'mock_token_' + Date.now(),
  };
  Taro.setStorageSync('userInfo', mockUser);
  return mockUser;
};
```

### 6.2 后期真实微信授权登录方案（预留接口）

```typescript
// 后续替换为真实实现
export const wxLogin = async () => {
  // Step 1：调用 Taro.login() 获取 code
  const { code } = await Taro.login();

  // Step 2：将 code 发送到云函数 / 腾讯云函数
  const res = await request('/api/user/login', { code });

  // Step 3：存储 token + openId
  Taro.setStorageSync('userInfo', res.data);
  return res.data;
};
```

> **隐私合规**：仅获取头像、昵称，不收集敏感信息；需在小程序后台配置「用户信息接口」权限。

## 十、后续云服务切换方案

当一期 Mock 验证完毕后，按如下步骤切换为真实服务：

1. **微信云开发**（推荐小程序端）
   - 在 `request.ts` 中将 Mock adapter 替换为 `wx.cloud.callFunction()`
   - 云函数覆盖：`getRecipes` / `getRecipeDetail` / `uploadRecipe` / `login` / `addComment`
   
2. **腾讯云函数**（APP 端 / 统一 HTTP）
   - 将 Mock adapter 替换为 `Taro.request()` HTTP 调用
   - 接口基础路径通过 `.env.prod` 中 `TARO_APP_API_BASE` 控制

3. **图片上传**
   - 小程序端：`wx.cloud.uploadFile()` → 云存储
   - APP 端：直传腾讯云 COS

> **切换成本极低**：只需修改 `services/request.ts` 中的 adapter，所有 Service 层、页面层代码无需改动。

## 十一、关键约束 & 注意事项

| 约束项 | 说明 |
|--------|------|
| 菜谱步骤 ≤ 8 步 | 表单层做前端校验 |
| 制作时长 ≤ 30 分钟 | 超出时给用户提示，允许特殊标注后发布 |
| 小程序代码包 ≤ 2MB | Sprint 4 优化时启用分包（`subPackages`） |
| APP 包体 ≤ 50MB | 避免引入过大 Native 依赖 |
| 无审核机制 | 前端发布时展示合规引导文案 |
| 图片懒加载 | 使用自定义 `LazyImage` 组件封装 |
| 本地缓存策略 | 收藏/草稿存 Storage，热门菜谱列表缓存 5 分钟 |
